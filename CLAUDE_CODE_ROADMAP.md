## 🟢 СЕЙЧАС — запускаем сегодня

### 1. Hooks — защита от поломки кода

**Проблема:** `app.py` — 640 KB. Одна лишняя скобка → сервер падает, а узнаём только
когда проверяем вручную.

**Решение:** после каждого Edit → автоматическая проверка синтаксиса.

Создать файл `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -m py_compile app.py 2>&1 && echo '✅ app.py OK' || echo '❌ СИНТАКСИЧЕСКАЯ ОШИБКА в app.py'"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": ".*",
        "hooks": [
          {
            "type": "command",
            "command": "git diff --name-only HEAD 2>/dev/null | head -20 | sed 's/^/  📝 /' || true"
          }
        ]
      }
    ]
  }
}
```

**Что получаем:**
- После каждого изменения файла → мгновенно видим есть ли ошибка синтаксиса
- В конце сессии → список изменённых файлов (не забудем сделать git commit)

### 2. PostgreSQL MCP — живые данные БД в разговоре

**Проблема:** чтобы посмотреть данные в БД нужно писать скрипт или лезть в psql.
Диагностика занимает 10–15 минут вместо одного вопроса.

**Решение:** подключить MCP-сервер PostgreSQL → я буду напрямую делать запросы.

**Установка:**
```bash
npm install -g @modelcontextprotocol/server-postgres
```

Добавить в `.claude/settings.json` (в блок верхнего уровня):

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://postgres:ПАРОЛЬ@nozomi.proxy.rlwy.net:25894/railway"
      ]
    }
  }
}
```

> ⚠️ Пароль вставлять из `.env` → `DATABASE_URL`. Не коммитить settings.json с паролем в git.
> Добавить `.claude/settings.json` в `.gitignore`.

**Что получаем — примеры вопросов которые я смогу ответить мгновенно:**
- "Сколько ниш сейчас в БД и когда последнее обновление?"
- "Покажи 5 ниш с самым высоким score но нулевой выручкой"
- "Есть ли ниши у которых нет mpstats_path?"
- "Проверь последние 10 строк price_history"

Вместо написания скрипта → просто спрашиваешь меня.

### 3. Loop — тест 5–7 ниш (задача 1.3 из MASTER_PLAN)

**Проблема:** нужно прогнать несколько ниш через PDF-генератор и убедиться что всё работает.
Делать руками — скучно и легко пропустить ошибку.

**Решение:** `/loop` запускает одну задачу повторно по списку, сам контролирует прогресс.

**Как использовать:**
```
/loop Проверь генерацию PDF для следующих ниш по очереди:
1. Смартфоны
2. Кофемашины
3. Чехлы для телефонов
4. Йогаматы
5. Детские игрушки
Для каждой ниши: запусти генерацию, проверь что PDF создался, выведи размер файла
и первые предупреждения если есть. Переходи к следующей автоматически.
```

**Что получаем:** я прохожу по всему списку без остановок, докладываю по каждой нише,
в конце — сводный отчёт что работает, что сломано.

## 🟡 ФАЗА 3 — когда пошли первые клиенты

### 4. Slash-команды (кастомные Skills)

Когда проект стабилизируется, нужны быстрые команды для рутины.
Создаются в `.claude/commands/` как markdown-файлы.

**`/pdf-test`** — протестировать PDF для одной ниши:
```markdown
# Тест PDF генерации
Запусти генерацию PDF для ниши: $ARGUMENTS
Проверь: файл создался, размер > 100KB, нет ошибок в консоли.
Выведи: путь к файлу, размер, время генерации.
```

**`/db-status`** — здоровье базы данных:
```markdown
# Статус базы данных
Через PostgreSQL MCP проверь:
1. Сколько всего ниш
2. Сколько ниш с score > 0
3. Сколько ниш без mpstats_path
4. Дата последнего обновления данных
5. Есть ли ниши с нулевой выручкой больше месяца
Выведи сводку одним блоком.
```

**`/repair-check`** — что нужно починить:
```markdown
# Аудит битых данных
Запусти python scripts/check_quality.py
Выведи только проблемные ниши (топ-10 по критичности).
Предложи какой скрипт из scripts/ запустить для починки.
```

**Как создать:**
```bash
mkdir -p .claude/commands
# создать файлы .md для каждой команды
```

### 5. Routines — автомониторинг без тебя

Облачные агенты Claude которые запускаются по расписанию. Ты их настраиваешь один раз.

**Routine 1: Утренний дозор (каждый день в 09:00)**
```
Проверь платформу WB SaaS:
1. Сделай GET /health на https://[твой домен]/
2. Через PostgreSQL MCP: сколько ниш обновлялось за последние 24 часа?
3. Если платформа не отвечает ИЛИ обновлений не было больше 48 часов — 
   отправь уведомление (push notification)
Иначе: тихо завершись.
```

**Routine 2: Еженедельное качество данных (каждый понедельник)**
```
Запусти аудит данных:
1. Через PostgreSQL MCP: найди ниши у которых score изменился > 20% за неделю
2. Найди ниши с нулевой выручкой которые раньше имели ненулевую
3. Составь краткий отчёт — что изменилось, что требует внимания
Сохрани отчёт в файл weekly_report_ДАТА.txt
```

**Запустить через:** `/schedule` команду в Claude Code.

## 🔴 ФАЗА 4 — автоматизация (бот + Mini App)

### 6. Telegram MCP

Когда Telegram-бот будет готов, MCP позволит мне работать с ним напрямую:
- Читать входящие сообщения и заявки
- Тестировать ответы бота без ручной отправки
- Мониторить очередь заявок

**Что нужно:** `mcp-telegram` сервер (установка аналогична postgres MCP).

Добавляется в тот же `settings.json`:
```json
"mcpServers": {
  "postgres": { ... },
  "telegram": {
    "command": "npx",
    "args": ["-y", "mcp-telegram", "--token", "BOT_TOKEN"]
  }
}
```

### 7. Loop для мониторинга клиентских заявок

Когда заявки идут потоком — `/loop` следит за очередью:

```
/loop каждые 30 минут:
Через PostgreSQL MCP проверь таблицу orders (или аналог).
Если есть новые необработанные заявки — выведи список.
Если заявка висит > 2 часов без ответа — подними флаг.
```

## Итоговая схема

```
СЕЙЧАС
├── Hooks          → .claude/settings.json → защита от поломки кода
├── PostgreSQL MCP → .claude/settings.json → живые данные без скриптов
└── Loop           → /loop [задача]        → тест ниш (задача 1.3)

ФАЗА 3 (первые клиенты)
├── Slash-команды  → .claude/commands/*.md → /pdf-test /db-status /repair-check
└── Routines       → /schedule             → утренний дозор + еженедельный аудит

ФАЗА 4 (автоматизация)
├── Telegram MCP   → settings.json         → Claude управляет ботом
└── Loop           → /loop                 → мониторинг очереди заявок
```

```bash

echo ".claude/settings.json" >> .gitignore
```
