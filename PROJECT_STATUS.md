Точка входа для возврата к проекту после паузы. Если ничего не помнишь — читай сверху вниз, этого достаточно, чтобы сориентироваться за 5 минут.

## Что это за проект

WBAnalyzer — SaaS для продавцов Wildberries: платные PDF-отчёты по товарным нишам (аналитика, цена входа, риски) через Telegram-бота, Mini App и сайт-лендинг.

Прод — монолит `app.py` (~11k строк, `http.server`, не Flask/FastAPI), задеплоен на Railway. Подробная архитектура — в `CLAUDE.md` в корне репозитория, здесь только карта и текущие проблемы.

---

## Карта сервисов на Railway

Один GitHub-репозиторий (`eastbridgehubVladimir/wb-analyzer`), три Railway-сервиса из него же, с разными Start Command:

| Сервис (Railway) | Что запускает | Роль |
|---|---|---|
| `wb-analyzer` | `python3 app.py` | Основной веб: сайт, лендинг, PDF-генерация, все `/api/*` |
| `trustworthy-presence` | `python3 warehouse_monitor.py` | Cron раз в ~2ч: мониторинг атак на склады WB, уведомления в Telegram |
| `zealous-expression` | `pip install -r requirements.txt && python3 telegram_bot.py` | Telegram-бот (aiogram), long-polling, поиск ниш, выдача PDF |

Все три читают `niche_updater.py`/`pdf_auto.py` из того же репозитория. `backend/` (FastAPI) существует в репо, но **не задеплоен нигде** — отдельная, неактивная ветка разработки.

## Известные открытые проблемы на 2026-10-22

1. **Ротация секретов после security-инцидента Railway (21.10.2026)** — Railway сообщили, что злоумышленник мог получить расшифрованные environment variables части клиентов. Статус ротации на момент написания:
   - ✅ `ANTHROPIC_API_KEY` — новое значение установлено в Railway Variables на всех 3 сервисах (`--skip-deploys`), **но ещё не задеплоено** (деплои Railway были частично заморожены инцидентом) и старый ключ в консоли Anthropic ещё не отозван.
   - ⬜ `TELEGRAM_BOT_TOKEN`, `MPSTATS_TOKEN`, `FIRECRAWL_API_KEY`, `WB_API_KEY`, пароль Postgres (`DATABASE_URL`) — **ротация не начата**.
   - Если читаешь это не в день написания — проверь `status.railway.com` (инцидент `QH8L8B3E`) и доведи ротацию до конца по схеме: новое значение у провайдера → `railway variable set ... --skip-deploys` → когда деплои разморозят → `railway redeploy` → проверить по логам, что сервис реально отвечает новым ключом → только потом отзывать старое значение у провайдера.

2. **MPStats блокирует датацентровые/VPN IP (QRATOR, 403 "Access Blocked")** — подтверждено с локальной машины через несколько разных VPN-серверов (Mullvad, разные страны — блокировка по всему провайдеру, не по одному IP). Один раз зафиксирован такой же 403 и с IP самого Railway — не до конца подтверждено, возможен тот же тип блокировки на проде.

3. **Обновление `niches` стоит с 2026-06-12** (~4+ месяца). Корневая причина — `update_niches.py` всегда был ручным скриптом (не cron), плюс однократный запрос `endRow:9999` физически не мог вернуть больше 500 записей (документированный лимит MPStats). Фикс с пагинацией (≤500/запрос) и общим Postgres-флагом квоты написан (`update_niches.py`, `niche_updater.py`), покрыт мок-тестами, **закоммичен (`a026a1d`), но не задеплоен и не проверен вживую** — упёрлись в п.1/п.2.

4. **Firecrawl: `402 Client Error`** на каждом прогоне `trustworthy-presence` (поиск новостей об атаках на склады) — кончились кредиты/оплата на аккаунте Firecrawl. Не связано с security-инцидентом, просто нужно продлить подписку.

5. **`/webhook/payment` в `app.py`** — заглушка (`webhook_not_configured`). Реального эквайринга (ЮKassa и т.п.) ещё нет, хотя схема БД (`orders`, `order_leads`) уже готова под него.

Используются по сервисам (где именно — см. карту выше):

| Переменная | Назначение | Где используется |

Актуальные значения — только в Railway Variables (`railway variable list --service <имя>`) и локально в `.env` (не в git, см. `.gitignore`). Никогда не в репозитории и не в чате открытым текстом.

## С чего начать после паузы

1. Проверить `status.railway.com` — нет ли открытого инцидента.
2. Быстрый пробный запрос к MPStats (`/subjects/select`, минимальный диапазон) — не 403/429.
3. `git log --oneline -10` — что было сделано последним, задеплоено ли.
4. `railway service list --json` (или дашборд) — у всех трёх сервисов `replicas.running: 1`, `status: SUCCESS`.
5. Проверить раздел «Известные открытые проблемы» выше — актуален ли он ещё, или часть уже закрыта.

## Правило: коммит и пуш сразу

Каждое завершённое изменение коммитится и пушится на GitHub сразу после проверки — не копится в рабочем дереве до «удобного момента». Если изменение требует живой проверки, которая временно недоступна (например, во время инцидента на Railway) — это единственное исключение: изменение остаётся закоммиченным локально, но решение о пуше явно озвучивается и ждёт подтверждения, а не просто откладывается молча.
